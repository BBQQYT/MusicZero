# MusicZero

[English README](README.md)

MusicZero — один музыкальный плеер со сменными источниками: **Яндекс Музыка**, **YouTube Music**, **локальная папка** и **радио Icecast**. Программа `mz` отвечает за аудиовывод, очередь, управление, предзагрузку следующего трека и интеграцию с рабочим столом Linux. Модули работают отдельными исполняемыми файлами.

## Установка

### Linux x86_64

Нужны `curl` и Python 3.8+:

```sh
curl -fsSL https://raw.githubusercontent.com/BBQQYT/MusicZero/main/install-linux.py | python3
```

Установщик выбирает самый новый опубликованный релиз с Linux-архивом, включая автоматические предварительные сборки, проверяет SHA-256 от GitHub и устанавливает файлы в `~/.local/bin`. Повторный запуск обновляет программу. Пользовательские настройки и папки собственных модулей сохраняются. Старые архивы могут содержать только YMZ и YouMZ.

Установщик автоматически открывает TUI-мастер, в том числе при запуске через `curl`. Управление: стрелки вверх/вниз (или j/k), Enter — подтвердить, Esc — отменить. Можно выбрать каталог, добавить `mz` в PATH Bash/Zsh/Fish, установить недостающие пакеты через apt/dnf/pacman/zypper (sudo может запросить пароль), настроить Local/Icecast и войти в Яндекс/YouTube Music. Дополнительное меню содержит пути FFmpeg, SoundFont, прокси/TLS/буфер радио и предпочтения «Моей волны». Для входа в YouTube нужны Firefox или Chromium/Chrome и графическая сессия. Установка пакетов и изменение настроек оболочки добровольны; неудачную настройку можно повторить без переустановки.

```sh
# Повторная настройка уже установленной программы
curl -fsSL https://raw.githubusercontent.com/BBQQYT/MusicZero/main/install-linux.py | python3 - --tui --setup-only
# Автоматизация: только установка, без вопросов
curl -fsSL https://raw.githubusercontent.com/BBQQYT/MusicZero/main/install-linux.py | python3 - --non-interactive
```

`--tui` требует управляющий терминал (`/dev/tty`) и заданный `TERM`; без терминала по умолчанию выполняется только установка. Мастер использует стандартный модуль Python `curses`, пакет dialog не требуется. Зависимости проверяются для выбранного источника и устанавливаются только по выбору пользователя. Esc сохраняет уже выполненную установку и записанные настройки. При обновлении все файлы подготавливаются до замены, а при ошибке замены предыдущие файлы восстанавливаются; транзакция при отключении питания или одновременных запусках установщика не гарантируется. Настройки и собственные модули сохраняются. После обновления перезапустите работающий плеер.

Если установщик сообщает, что каталог отсутствует в `PATH`, добавьте в настройки своей оболочки:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

`MUSICZERO_PREFIX` меняет префикс установки: исполняемые файлы попадут в `<prefix>/bin`. `MUSICZERO_TAG` выбирает конкретный релиз. При передаче скрипта через конвейер переменные задаются для Python:

```sh
curl -fsSL https://raw.githubusercontent.com/BBQQYT/MusicZero/main/install-linux.py |
  MUSICZERO_PREFIX="$HOME/.local" MUSICZERO_TAG="build-123" python3
```

Замените `build-123` существующим тегом релиза. После обновления перезапустите работающий плеер, чтобы он использовал новые файлы.

### Ручная установка и Windows

Скачайте архив для своей системы из [Releases](https://github.com/BBQQYT/MusicZero/releases) и распакуйте **папку `musiczero` целиком**, сохранив модули рядом с плеером:

```text
musiczero/
├── mz                         # mz.exe в Windows
├── README.md
├── README_RU.md
└── modules/
    ├── ymz/                   # module.json + ymz-module
    ├── youmz/                 # module.json + youmz-module
    ├── local/                 # module.json + local-module
    └── icecast/               # module.json + icecast-module
```

В Windows исполняемые файлы модулей также имеют расширение `.exe`. В PowerShell используйте `./mz.exe` вместо `mz`:

```powershell
./mz.exe set local path "C:\Users\yourname\Music"
./mz.exe local
```

### Требования для работы

| Компонент | Что требуется |
| --- | --- |
| Плеер | Работающий аудиовывод; в Linux — ALSA либо настроенный интерфейс ALSA к PipeWire/PulseAudio |
| Трей и MPRIS в Linux | Пользовательская сессия D-Bus; для трея — панель с поддержкой StatusNotifierItem |
| YMZ | Аккаунт Яндекс Музыки и действующий OAuth-токен |
| YouMZ | Вход через Firefox, LibreWolf, Chromium или Chrome; для аудио — `yt-dlp` в PATH |
| Локальная папка | `ffmpeg` и `ffprobe` в PATH |
| Старые трекерные форматы | FFmpeg, собранный с `libopenmpt` |
| MIDI | Дополнительно `fluidsynth` в PATH и настроенный банк SF2/SF3 |
| Icecast | `ffmpeg` в PATH и прямой HTTP(S) mountpoint радиостанции |

FFmpeg, yt-dlp, браузеры и банки SoundFont не входят в поставку MusicZero. Для Local и Icecast можно указать пути к программам в настройках. При недоступной интеграции с рабочим столом управление через CLI остаётся доступным; ошибки MPRIS выводятся в журнал. В Windows пока нет собственного трея и системных медиаклавиш.

## Быстрый запуск и управление

Запустите плеер в одном терминале и оставьте его открытым. Команды управления выполняйте во втором. Запуск другого источника при работающем плеере переключает существующий процесс.

```sh
mz modules
mz login ymz
mz ymz
```

Во втором терминале:

```sh
mz status
mz toggle
mz next
mz playlists
mz playlist 2
mz switch youmz
mz quit
```

| Команда | Действие |
| --- | --- |
| `mz` | Показать статус работающего плеера или справку |
| `mz modules` | Список установленных модулей |
| `mz start <id>` или `mz <id>` | Запустить источник либо переключить работающий плеер |
| `mz switch <id>` | Переключить источник, очистив текущий трек и очередь |
| `mz login <id>` | Интерактивный вход в сервис |
| `mz status` | Источник, плейлист, текущий трек, позиция и длительность |
| `mz seek <время>` | Позиция в секундах или MM:SS/HH:MM:SS; +/− задаёт относительное смещение |
| `mz play`, `mz pause`, `mz toggle` | Воспроизведение, пауза, переключение состояния |
| `mz next` | Следующий трек; для радио — новое подключение к станции |
| `mz prev` / `mz previous` | Предыдущий трек; до пяти шагов назад |
| `mz history [id]` | Пять последних разных треков, новые сверху; с указанием модуля работает без плеера |
| `mz replay <номер>` | Прослушать трек из истории активного модуля; номера **начиная с 1** |
| `mz stop` | Остановить воспроизведение, оставив плеер запущенным |
| `mz quit` | Завершить плеер |
| `mz playlists` | Плейлисты или станции активного источника |
| `mz playlist <id\|номер>` | Выбрать ID или номер **начиная с 1**; без аргумента — показать выбор |
| `mz config [id]` / `mz tui [id]` | Полное TUI настроек с выбором русского/английского; работает без запущенного плеера |
| `mz settings` | Настройки активного источника |
| `mz settings <id>` | Настройки указанного модуля, в том числе до запуска |
| `mz set <ключ> <значение>` | Изменить настройку активного источника |
| `mz set <id> <ключ> <значение>` | Настроить указанный модуль до или во время воспроизведения |
| `mz help`, `mz version` | Справка и версия |

При поиске модуля в CLI регистр имени не учитывается. Пути, URL и JSON заключайте в кавычки. Изменение настроек активного Local/Icecast сбрасывает очередь и загрузку, чтобы применить новые параметры. Некорректное значение возвращает ошибку. Остальные команды управления и выбора плейлиста требуют работающего плеера.

Перемотка работает для скачанных треков YMZ, YouMZ и Local, в том числе на паузе. Текущий трек и предзагрузка следующего сохраняются. `status` показывает позицию и известную длительность. Длительность декодера имеет приоритет над метаданными модуля; неизвестная длительность не зажимает перемотку в ноль. При известной длительности позиция ограничивается началом/концом трека. Для прямого эфира Icecast перемотка недоступна. Linux MPRIS Seek/SetPosition используют тот же обработчик и отправляют Seeked; SetPosition игнорирует устаревший ID трека.

```sh
mz seek 90       # перейти к 90 секундам
mz seek 1:30.5   # перейти к 90,5 секундам
mz seek +15     # вперёд на 15 секунд
mz seek -10     # назад на 10 секунд
```

Плеер хранит пять прошлых треков отдельно для каждого модуля; история сохраняется при смене плейлиста, источника и после перезапуска. В историю попадает трек, который начал играть, а затем завершился или был пропущен. `mz prev` возвращает назад по истории; `mz next` возвращает по оставленным трекам, затем продолжает прежнюю очередь. Повтор начинается с начала и заново получает аудио: трек должен оставаться доступным у источника. При повторе треков волны YMZ курсор продолжения сохраняется, старые сигналы партии не отправляются повторно. Прямой эфир не входит в историю: прошлую трансляцию нельзя запросить как отдельный трек. В Linux доступны кнопка Previous в MPRIS и меню предыдущего трека/истории в трее.

```sh
mz prev          # прослушать предыдущий трек
mz history       # пять последних треков активного модуля
mz replay 3      # прослушать трек №3; next вернёт к прерванному треку
mz history ymz   # посмотреть сохранённую историю даже без запущенного плеера
```

## Трей и пользовательский сервис Linux

Установщик предлагает сохранить, включить или выключить значок трея и содержит кнопку «Install service / Установить сервис». Выберите модуль для автозапуска при входе; запуск сейчас выбирается отдельно. Неинтерактивная установка сохраняет настройки и не устанавливает сервис. Нужен релиз с командами `mz tray` и `mz service`; старые файлы продолжают прежний сценарий настройки.

В `mz config` раздел «Плеер и папки» содержит «Показывать значок в трее». Раздел «Сервис / автозапуск» позволяет установить сервис, посмотреть статус, запустить, остановить, перезапустить и удалить его. Перед запуском настройте выбранный модуль и выполните вход. Оба меню поддерживают русский и английский.

```sh
mz tray off                    # выключить трей при последующих запусках; on включает
mz service install ymz         # выбрать YMZ и включить автозапуск при входе
mz service start
mz service status
mz service restart             # применить настройки трея или обновлённый unit
mz service stop
mz service remove              # остановить и отключить автозапуск, сохранив настройки
```

Unit хранится в `<корень настроек>/systemd/user/musiczero.service` и управляется через `systemctl --user`, без sudo. Установка включает автозапуск без немедленного воспроизведения. Сервис запускает установленный файл с выбранным модулем и сохранённым плейлистом. Пути настроек/модулей и программ сохраняются; токены и сессии аккаунтов в unit не записываются. Повторная установка обновляет unit для следующего запуска; работающий сервис перезапустите отдельно для применения изменений. Если плеер уже работает вручную, завершите его перед запуском сервиса. Журнал: `journalctl --user -u musiczero.service`. В Linux без пользовательского менеджера systemd можно запускать плеер вручную. В Windows меню systemd отсутствует; Windows и Linux-сборки без функции tray не могут включить значок трея.

`install.sh` также открывает меню настроек, если stdin/stdout подключены к терминалу; `MUSICZERO_SETUP=0` пропускает его. Выбор трея и последний источник сервиса сохраняются как `tray_enabled` и `service_module` в `mz/settings.json`.

## Меню настроек

```sh
mz config          # Все настройки
mz config icecast  # Сразу открыть модуль
```

Встроенное меню не требует Python. Стрелки или j/k выбирают пункт, Enter открывает и сохраняет, Esc возвращает назад или отменяет ввод, Ctrl+U очищает поле, Ctrl+C закрывает меню. Поддерживаются вставка из буфера, кириллица, прокрутка и изменение размера терминала. «Язык / Language» переключает все экраны и подсказки между русским и английским; выбор сохраняется в `mz/settings.json`.

Меню показывает все поля `settings` установленных модулей, включая новые поля сторонних провайдеров. Есть все параметры Local, настроение/разнообразие/язык волны YMZ, токен и вход, прокси/браузер/сессия YouMZ, плейлисты и все настройки Icecast. Станции добавляются, редактируются и удаляются через форму, включая ID, адрес сервера, mountpoint и авторизацию. Пароли и токены скрыты; изменение других полей сохраняет существующий пароль. Вход открывает штатную процедуру сервиса и возвращает в меню.

Значения сохраняются сразу после подтверждения, проверяются модулем, ошибки отображаются в меню. Плейлист можно выбрать до запуска плеера. Настройки активного Local/Icecast применяются через IPC со сбросом старой загрузки. Параметры волны требуют авторизации и сети; при недоступности сервиса меню и вход остаются доступны.

Раздел плеера задаёт папку модулей, фильтр журналирования и папку временного аудио. Пустые значения возвращают стандартное поведение. `MZ_MODULES_DIR` и `RUST_LOG` имеют приоритет над сохранёнными значениями; для них перезапустите плеер. Папка временного аудио применяется к новым загрузкам и процессам модулей. Пути конфигов/кэша и активные переменные окружения показаны отдельно.

## Яндекс Музыка (YMZ)

```sh
mz login ymz
```

Модуль открывает [ym-token.marshal.dev](https://ym-token.marshal.dev/), ждёт вставки OAuth-токена в терминале, проверяет его через Яндекс Музыку и сохраняет. Если браузер не открылся, перейдите по показанной ссылке самостоятельно: ввод токена продолжит работать.

```sh
mz ymz
mz playlists
mz playlist wave
mz settings ymz
mz set ymz mood calm
```

По умолчанию используется `wave` — «Моя волна». Плейлисты аккаунта имеют ID вида `playlist:12345`; выбирайте ID из `mz playlists` или номер в списке. Настройки волны: `mood`, `diversity`, `language`; допустимость значений проверяет сервис.

Токен хранится в `~/.config/ymz/token` в Linux или `%APPDATA%\ymz\token` в Windows. Сохранённый токен имеет приоритет над `YM_TOKEN`; переменная используется, когда подходящего файла нет.

## YouTube Music (YouMZ)

```sh
mz login youmz
```

1. Откроется поддерживаемый браузер с отдельным временным профилем, первоначально без параметров отладки.
2. Войдите в аккаунт и дождитесь появления библиотеки YouTube Music.
3. **Закройте это окно браузера.** Команду входа оставьте работающей.
4. Модуль повторно откроет временный профиль, получит активную сессию через интерфейс отладки браузера, проверит её и сообщит об успешном входе.

Cookie-файлы вашего обычного профиля браузера не читаются. Создавать Google OAuth-приложение или клиент TV/device не требуется. Ctrl+C отменяет вход.

```sh
mz youmz
mz playlists
mz playlist RDMM
```

`RDMM` — персональный микс по умолчанию. Для воспроизведения нужен `yt-dlp`: вход в аккаунт не устанавливает его. При загрузке аудио cookies передаются через временный файл Netscape с областью действия YouTube. При нормальном завершении запроса файл удаляется.

| Параметр | Назначение |
| --- | --- |
| `YOUMZ_BROWSER` | Путь к браузеру, если автоматический поиск не сработал |
| `YOUMZ_SESSION` | Строка сессии; имеет приоритет над сохранённым файлом |
| `~/.config/youmz/session` | Сохранённая сессия; в Windows — `%APPDATA%\youmz\session` |
| `~/.config/youmz/proxy` / `YOUMZ_PROXY` | Прокси; непустой файл имеет приоритет над переменной |

YouMZ предоставляет `proxy`, `browser` и скрытую `session` через `mz config youmz` и `mz settings youmz`. Для скриптов: `mz set youmz <ключ> <значение>`. Сохранённый браузер используется, если его не переопределяет `YOUMZ_BROWSER`. Если Google отказывает во входе, проверьте вход в браузере, открытом обычным способом, затем повторите двухэтапный вход MusicZero. Старые ошибки OAuth-клиента означают устаревшие исполняемые файлы: обновите плеер **и** модули.

## Локальная папка с музыкой

```sh
mz set local path "$HOME/Music"
mz settings local
mz local
```

`path` должен указывать на существующий каталог. Для работающего плеера используйте `mz switch local`. Единственный плейлист Local — `all`. Сканирование определяет аудио по содержимому, без списка разрешённых расширений, читает теги названия и исполнителя и при необходимости использует имя файла. Одновременно проверяются до восьми файлов; метаданные неизменившихся файлов повторно берутся из индекса по размеру и времени изменения. На Unix имена файлов с невалидным UTF-8 сохраняются в индексе без потерь и получают разные ID; отображаемые названия заменяют невалидные символы.

### Настройки Local

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `path` | пусто | Существующий каталог; путь с пробелами заключайте в кавычки; `~/` раскрывается при наличии HOME |
| `recursive` | `true` | Сканировать подпапки |
| `hidden` | `false` | Включать имена, начинающиеся с `.` |
| `shuffle` | `false` | Перемешивать библиотеку при каждом заполнении очереди |
| `scan_limit` | `10000` | Максимум проверенных файлов и каталогов, 1–100000 |
| `probe_timeout` | `5` | Тайм-аут проверки одного файла, 1–30 секунд |
| `ffmpeg` | `ffmpeg` | Имя или путь исполняемого файла FFmpeg |
| `ffprobe` | `ffprobe` | Имя или путь ffprobe |
| `fluidsynth` | `fluidsynth` | Имя или путь MIDI-рендерера |
| `soundfont` | пусто | Существующий банк SF2/SF3 для MIDI |

```sh
mz set local recursive true
mz set local shuffle true
mz set local soundfont "/путь/к/GeneralUser.sf2"
```

### Форматы и ограничения

Поддержка зависит от сборки FFmpeg: FLAC, WAV, MP3/MP2, AAC/M4A/ALAC, Ogg/Vorbis/Opus, WMA, AIFF, AU, VOC, WavPack, APE, TTA, CAF, AC3, ADPCM и другие доступные ей форматы. Для MOD/XM/S3M/IT и других трекерных файлов нужен `libopenmpt`. MIDI определяется по заголовку и обрабатывается FluidSynth с настроенным SoundFont. Возможности установленного FFmpeg можно посмотреть через `ffmpeg -demuxers` и `ffmpeg -decoders`.

**Поддержка буквально всех исторических форматов не гарантируется.** Для SID и специализированных форматов, отсутствующих в FFmpeg/FluidSynth, нужны дополнительные декодеры, пока не подключённые к модулю. Смена расширения не делает повреждённый, неподдерживаемый или защищённый DRM файл воспроизводимым.

Local преобразует аудио в FLAC для декодирования плеером и предзагружает один следующий трек. Действуют ограничения конечного аудио: 512 MiB на подготовленный файл и 180 секунд на подготовку. Индекс метаданных ограничен 4 MiB. Первый проход по очень большой библиотеке может превысить 90-секундный тайм-аут запроса метаданных; промежуточный индекс сохраняется, поэтому повторный проход использует уже проверенные файлы. Символические ссылки не обходятся; воспроизведение разрешает пути внутри выбранного корня. Подробнее: [модуль Local](modules/local/README.md).

## Радио Icecast

Модуль слушает прямые HTTP(S) mountpoint потоков Icecast/Shoutcast. Вещание на сервер не реализовано.

```sh
mz set icecast url "https://radio.example.org:8443/live.ogg"
mz set icecast name "Моя станция"
mz settings icecast
mz icecast
```

Звук начинается после буферизации, до завершения потока. Радио использует ограниченный PCM-буфер в памяти: бесконечный временный файл не создаётся, второе соединение для предзагрузки не открывается. Перемотка отключена. После длительной паузы выполните `mz next`, чтобы подключиться к актуальному эфиру. Статус и MPRIS показывают название станции; смена названий песен из ICY **пока не отображается**.

### Настройки Icecast

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `station` | `default` | ID станции, которую изменяют станционные параметры ниже |
| `stations` | одна пустая станция | JSON-массив `{id,name,url,username,password}`; 1–200 станций с уникальными ID |
| `url` | пусто | Полный HTTP(S) URL выбранной станции; учётные данные задаются отдельно |
| `server` | — | Изменить URL сервера выбранной станции, сохранив mountpoint |
| `mountpoint` | — | Путь вида `/live.mp3` на уже настроенном сервере |
| `name` | `Icecast` | Отображаемое название выбранной станции |
| `username`, `password` | пусто | HTTP Basic-аутентификация; пароль в выводе настроек скрыт как `***` |
| `proxy` | пусто | URL HTTP-прокси; пустая строка отключает его |
| `user_agent` | `MusicZero/0.3` | HTTP User-Agent |
| `reconnect` | `true` | Переподключение FFmpeg при EOF, сетевых ошибках, HTTP 429 и 5xx |
| `reconnect_delay_max` | `5` | Максимальная задержка переподключения FFmpeg, 1–60 секунд |
| `timeout` | `15` | Тайм-аут сетевого чтения, 1–120 секунд |
| `buffer_ms` | `1000` | Начальная буферизация и размер PCM-очереди, 250–10000 миллисекунд |
| `tls_verify` | `true` | Проверять HTTPS-сертификаты |
| `ca_file` | пусто | Файл CA для собственной HTTPS-инфраструктуры |
| `ffmpeg` | `ffmpeg` | Имя или путь FFmpeg |

Для передачи учётных данных используйте HTTPS. Значение `***` в выводе — маска, а не сохранённый пароль. `reconnect=false` отключает внутреннее переподключение FFmpeg; плеер по-прежнему повторяет закончившееся или неудачное воспроизведение. Изменение настроек активного Icecast закрывает старый поток и применяет новые параметры.

### Несколько станций

Замените примерные URL реальными адресами потоков:

```sh
mz set icecast stations '[{"id":"one","name":"Первая","url":"https://radio.example.org/one.mp3"},{"id":"two","name":"Вторая","url":"https://radio.example.org/two.ogg"}]'
mz icecast
mz playlists
mz playlist two
mz set icecast station two
mz set icecast buffer_ms 1500
```

`mz playlist` выбирает воспроизведение; `station` выбирает запись, которую изменяют `url`, `name`, `username` и другие станционные настройки. Специальный плейлист `default` следует значению `station`: выполните `mz playlist default`, чтобы вернуться к этому режиму. В PowerShell одинарные кавычки сохраняют JSON-строку. Подробнее: [модуль Icecast](modules/icecast/README.md).

## Настройки, кэш и переменные окружения

Корень настроек определяется через `XDG_CONFIG_HOME`/`~/.config` в Linux и `APPDATA` в Windows. Корень кэша — через `XDG_CACHE_HOME`/`~/.cache` в Linux и `LOCALAPPDATA` в Windows.

| Данные | Путь относительно соответствующего корня |
| --- | --- |
| Язык и настройки плеера | Конфиг: `mz/settings.json` |
| Токен YMZ | Настройки: `ymz/token` |
| Сессия и прокси YouMZ | Настройки: `youmz/session`, `youmz/proxy`, `youmz/browser` |
| Настройки Local | Настройки: `mz-local/settings.json` |
| Станции и настройки Icecast | Настройки: `mz-icecast/settings.json` |
| Выбранный плейлист каждого модуля | Настройки: `mz/<id>.playlist` |
| Пять последних треков каждого модуля (только метаданные) | Настройки: `mz/<id>.history.json` |
| Индекс метаданных Local | Кэш: `mz-local/index.json` |

Учётные данные и настройки Local/Icecast сохраняются атомарно; новые файлы в Unix имеют права `0600`. Собственные модули самостоятельно управляют своими настройками.

Конечное аудио находится в системном временном каталоге, обычно `/tmp` в Linux. Хранятся текущий трек и один следующий, подготовленный или загружаемый. При нормальном освобождении файлы удаляются; аварийное завершение или принудительное убийство процесса может оставить их. Постоянного кэша скачанной музыки нет. Чтобы изменить временный каталог в Linux, создайте его и задайте `TMPDIR` перед запуском:

```sh
mkdir -p "$HOME/.cache/musiczero-tmp"
TMPDIR="$HOME/.cache/musiczero-tmp" mz local
```

`MZ_MODULES_DIR` переопределяет поиск модулей; иначе они ищутся рядом с фактическим исполняемым файлом, а не в текущем каталоге. `RUST_LOG` управляет журналом; по умолчанию плеер использует `warn,mz=info`. Управление в Linux идёт через `$XDG_RUNTIME_DIR/musiczero.sock`, а при отсутствии переменной — через каталог кэша плеера. Windows использует именованный канал. Плеер и управляющие команды должны использовать одинаковое окружение для подключения к одному процессу.

## Решение проблем

| Симптом | Что проверить |
| --- | --- |
| Команда `mz` не найдена | Путь, напечатанный установщиком, PATH; в PowerShell — `./mz.exe` |
| Модуля нет в `mz modules` | Полная папка рядом с плеером, имя и права исполняемого файла, `MZ_MODULES_DIR`; обычная сборка не собирает эту структуру автоматически |
| Старые ошибки OAuth или вход лишь предлагает создать файл токена | Обновить плеер и модули, перезапустить и использовать описанный выше вход |
| Google отказывает во входе | Вход в обычном браузере, затем двухэтапный вход во временном профиле; поиск браузера и `YOUMZ_BROWSER` |
| YouMZ не скачивает аудио | Наличие `yt-dlp` в PATH, его сообщения, сессия и прокси |
| В локальной папке нет треков | Существование `path`, FFmpeg/ffprobe, декодеры, рекурсия, скрытые файлы и предел сканирования |
| MIDI не воспроизводится | FluidSynth, читаемый SoundFont и корректный MIDI-файл |
| Радио не подключается или обрывается | Прямой mountpoint, авторизация, сеть/прокси, сообщения FFmpeg, тайм-аут и переподключение; CA для собственного HTTPS |
| Нет звука | Аудиоустройство и ALSA; даже с `--no-default-features` требуется аудиовывод |
| Нет трея или MPRIS | Пользовательская сессия D-Bus и поддержка панели; в Windows эти функции отсутствуют |
| Команда сообщает, что плеер не запущен | Сначала запустить источник; проверить одинаковый runtime-каталог и окружение |

## Сборка и проверка

Используйте стабильный Rust. Для Linux нужны `pkg-config` и заголовки ALSA, например `libasound2-dev`; CI также устанавливает `libsqlite3-dev`.

```sh
cargo build --workspace --release --locked
./install.sh
```

`install.sh` собирает и устанавливает четыре официальных модуля рядом с `mz`; `MUSICZERO_PREFIX` по умолчанию равен `~/.local`, а `CARGO_TARGET_DIR` учитывается. `bootstrap.sh` клонирует временную копию репозитория и запускает установщик; `MUSICZERO_REPO` и `MUSICZERO_REF` задают репозиторий и ветку/тег.

Сборка Windows в CI отключает стандартную возможность трея. Этот же параметр позволяет собрать Linux-версию без трея:

```sh
cargo build --workspace --release --no-default-features --locked
```

| Каталог / пакет | Назначение |
| --- | --- |
| `mz` / `mz` | CLI, IPC, воспроизведение, предзагрузка, live PCM и трей Linux |
| `MCZ` / `mcz` | Общие MPRIS, системные пути и завершение работы |
| `YMZ` / `ymz` | Модуль `ymz-module` |
| `YouMZ` / `youmz` | Модуль `youmz-module` и браузерный вход |
| `Local` / `local` | Модуль `local-module`: сканирование, метаданные и аудио |
| `Icecast` / `icecast` | Модуль `icecast-module`: станции, настройки и live PCM |
| `ModuleSupport` / `mz-module-support` | Общие настройки модулей, пути и запуск FFmpeg |

```sh
cargo test --workspace --locked
cargo test -p mz --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
```

Интеграционные smoke-тесты Linux требуют FFmpeg/ffprobe с `libopenmpt` и OpenSSL. Они создают синтетическое аудио, изолированные настройки, используют ALSA null, локальную HTTP-станцию с тестовой авторизацией и временный HTTPS CA. Ваши аккаунты и музыка не используются:

```sh
cargo build --workspace --locked
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/smoke_modules.py
python3 tests/smoke_https.py
python3 tests/smoke_seek.py
python3 tests/smoke_wave.py
python3 tests/smoke_history.py
python3 tests/smoke_config.py
python3 tests/smoke_service.py
```

Для уже собранных release-файлов задайте `MZ_TEST_PROFILE=release` при запуске Python. Тесты проверяют синтетический FLAC и старые форматы, определение по содержимому, теги, авторизованный live-поток и переключение источников. Успешная сборка сама по себе не подтверждает вход в реальные аккаунты или поддержку каждого формата.

Проверки настоящих аккаунтов запускаются отдельно: нужны сохранённая авторизация MusicZero (или `YM_TOKEN`/`YOUMZ_SESSION`), сеть и `yt-dlp`. Скрипт использует временные копии авторизации приложения, удаляет временные файлы после завершения и не читает профили браузеров. `--host` также проверяет воспроизведение и перемотку на паузе/после продолжения через ALSA null; физические колонки не проверяются. Эти проверки не запускаются в CI:

```sh
python3 tests/check_services.py --host
# Проверить только один сервис
python3 tests/check_services.py --module youmz --host
# Проверить продолжение волны за пределами первой партии
python3 tests/check_services.py --module ymz --host --wave-tracks 15
# Проверить возврат, повтор и продолжение на настоящих треках сервисов
python3 tests/check_services.py --host --wave-tracks 7 --history
```

CI собирает Linux x64 и Windows x64. Push в `main`/`master` публикует предварительный релиз `build-<номер запуска>` после успешной сборки обеих платформ; теги `v*` создают версионные релизы. Точные условия и упаковка: [.github/workflows/ci.yml](.github/workflows/ci.yml). Лицензия: [LICENSE](LICENSE).

## Написать свой модуль

Модуль можно написать на любом языке. Исполняемые файлы собираются отдельно для каждой платформы. Создайте `modules/<id>/module.json` и положите программу рядом:

```json
{
  "protocol": 1,
  "id": "demo",
  "name": "Мой сервис",
  "binary": "demo-module",
  "default_playlist": "main"
}
```

Имя папки должно совпадать с `id`; `id` и `binary` состоят из латинских букв, цифр, `_` и `-`. В `binary` не указывайте `.exe`: Windows добавляет его сама. Некорректные манифесты и отсутствующие программы пропускаются. Ответ `info` должен точно совпадать с полями протокола, ID, названия и плейлиста по умолчанию в манифесте.

Каждый запрос запускает новый процесс. В stdout пишите **только данные протокола**, диагностику — в stderr; при ошибке завершайтесь с ненулевым кодом. Конечное аудио возвращается в формате, который декодирует плеер, например MP3, M4A, WAV или FLAC.

| Команда | stdout |
| --- | --- |
| `info` | `{"protocol":1,"id":"demo","name":"Мой сервис","default_playlist":"main"}` |
| `playlists` | `{"playlists":[{"id":"main","name":"Основной"}]}` |
| `tracks main` | `{"tracks":[{"id":"track-1","title":"Трек","artist":"Исполнитель","duration_ms":120000,"art_url":""}]}` |
| `audio track-1` | Только закодированные аудиобайты |
| `settings` | `{"settings":{}}` либо заполненные настройки в этой обёртке |
| `set-setting key value` | Обновлённый `{"settings":{...}}`; необязательно, если настройки не изменяются |
| `login` | Необязательная интерактивная команда с терминальным вводом/выводом |

`info`, `playlists`, `tracks`, `audio` и `settings` обязательны. Возвращайте треки в порядке воспроизведения; ID передаётся обратно без изменений. JSON ограничен 4 MiB и 90 секундами. Конечное аудио — 512 MiB и 180 секундами, включая завершение процесса.

Для бесконечной подборки ответ `tracks` добавляет `"continuous":true`. Следующий запрос — `tracks <playlist> <after>`, где `after` — ID последнего завершённого или пропущенного трека. Хост убирает пересечения партий и хранит последние 256 ID. Обычные плейлисты сохраняют прежнее поведение. Необязательное поле трека `"feedback":"<batch-context>"` включает команду `feedback <event> <id> <context> <played_seconds>` с ответом `{"ok":true}`. События `trackStarted`, `trackFinished` и `skip` отправляются по порядку; секунды учитывают фактическое прослушивание без пауз. Перед запросом продолжения хост ждёт отправки накопленных событий. YMZ использует это расширение для «Моей волны».

Для live-аудио трек добавляет `"stream":true,"buffer_ms":1000`. Команда `audio` должна выдавать **сырой signed 16-bit little-endian PCM, 48000 Гц, два чередующихся канала** и может работать неограниченно долго. Плеер ограничивает буфер, начинает воспроизведение до EOF и отменяет чтение/модуль при переключении или выходе. На запуск даётся 60 секунд; `buffer_ms` ограничивается диапазоном 250–10000. Перемотка и предзагрузка второго live-потока отключены. Это расширение требует актуального плеера.

Отдельный crate [examples/module-template](examples/module-template) создаёт WAV-тон без зависимостей:

```sh
cargo build --release --manifest-path examples/module-template/Cargo.toml
```

Скопируйте его `module.json` и собранный `demo-module`/`demo-module.exe` в `modules/demo`. Для разработки подготовьте полные папки модулей и задайте `MZ_MODULES_DIR`: одних манифестов без исполняемых файлов недостаточно.
